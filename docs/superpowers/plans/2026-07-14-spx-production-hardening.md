# SPX Phase 6G-A Implementation Plan

> User authorization is limited to offline production hardening. Checkpoints replace commits because commit/push are explicitly forbidden.

1. Add six failing contract suites for canonical environments, crypto round trips/failures, readiness state transitions, order routing and mixed-batch rejection, secure settings semantics, and safe idempotent migration. Run them before production code and retain the RED evidence.
2. Add `SPX_Environment` with exact names, fixed URLs, normalization, host validation, and the exact implemented endpoint set. Refactor `SPX_API_Config` to use canonical constants and an injected credential store, with server constants first and encrypted options second.
3. Add `SPX_Secret_Storage` using salts-derived keys, Sodium secretbox, AES-256-GCM fallback, versioned authenticated payloads, and controlled decryption failure. Add `SPX_Credential_Store` with separate test/production records, masked metadata, constant-source detection, explicit preservation/deletion, fingerprints, and no cross-environment fallback.
4. Add `SPX_Credential_Migration` and config schema installation. Migrate only recognized same-environment legacy keys, encrypt before deletion, keep source data on failure, and make reruns harmless. Wire activation and safe boot-time version checks.
5. Harden `SPX_HTTP_Client`: require a canonical environment config, exact HTTPS origin/port/userinfo rules, exact relative endpoint allowlist, redirects disabled, and a production operation gate checked before signing or transport. Update all API services to accept environment-specific dependencies rather than silently constructing sandbox defaults.
6. Add `SPX_Order_Environment` to read canonical meta, normalize legacy meta, bind new shipments immutably, and reject conflicts. Add `SPX_Environment_Router` to create environment-aware API services and fail closed for production until Gate 6G-B.
7. Refactor tracking query/sync/scheduler so every batch is single-environment and Action Scheduler groups/retry arguments include environment. Preserve legacy test tracking behavior and reject mixed input before service calls.
8. Add `SPX_Production_State` and `SPX_Production_Readiness`. Store verification fingerprint/timestamp separately, invalidate on credential changes, cap offline transitions at `readiness_pending`, and expose hard checks and warnings without enabling production.
9. Add the production settings section to the existing SPX WooCommerce page. Implement capability/nonce/POST/PRG, blank-secret preservation, explicit deletion, readonly constant-managed fields, safe notices, and no rendered secret/ciphertext. Remove editable API host/credentials from shipping-zone instances while preserving fixed-rate and Mock Provider behavior.
10. Update README and API analysis with environment constants, encrypted fallback behavior, state semantics, immutable order environment, offline limitations, and Gate 6G-B prerequisites.
11. Add offline runtime fixtures A–D and browser fixture setup/cleanup under `tests/runtime`, always loading the network deny policy and never reading real `.env` credentials. Verify settings UI without capturing secret values.
12. Run PHP 7.4 lint, all unit suites, API/address/rate/shipment/tracking/status/checkout/security regressions, existing offline integrations, HPOS compatibility and `unsynced=0`, scheduler/mixed-batch/duplicate checks, admin/customer smoke, protected-order snapshot comparison, and sanitized debug/WooCommerce/network audits. Report blockers honestly; do not claim production verification.
