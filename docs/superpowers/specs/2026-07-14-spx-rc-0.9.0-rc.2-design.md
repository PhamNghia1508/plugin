# SPX Express 0.9.0-rc.2 Release Integrity Design

## Scope

Produce a local, reviewable release candidate from the current SPX Express plugin without calling any SPX endpoint or mutating WooCommerce order 642. The only product changes are UTF-8 copy remediation and the version bump to `0.9.0-rc.2`; the payment, COD, shipping-rate, shipping-zone, cache-signature, and Create-lock behavior must remain unchanged.

## Release contract

- A source-level integrity test scans every distributable text file for known mojibake byte sequences and verifies every version surface.
- The same test proves the tagged source contains `SPX_Payment_Resolver`, canonical payment/COD propagation, positive-rate fail-closed guards, matched shipping-zone instance signatures, and the atomic `add_option()` Create lock.
- The repository is local only. Secrets, runtime state, backups, and generated release artifacts are ignored.
- The ZIP is generated by `git archive` from annotated tag `v0.9.0-rc.2`, with developer-only files excluded through export attributes.
- Clean-install and upgrade verification run in isolated/disposable WordPress state with SPX outbound traffic denied.

## Verification and safety

Run the new test once while red, make the smallest source changes, then run it green. Before tagging, run PHP 7.4 and 8.2 suites, lint, JavaScript syntax checks, HPOS and checkout regressions, and source/security scans. After archiving, inspect the ZIP independently, install it into clean and upgrade fixtures, verify Vietnamese rendering, and repeat the no-secret/no-SPX audit. Record only booleans, counts, hashes, and masked values for order/runtime checks.
